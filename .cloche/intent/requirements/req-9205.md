Duration/elapsed formatting rolls hours into days once past 24h (e.g. '3d 4h', dropping minutes) and drops down to days-only past 7 days (e.g. '12d'); below 24h it stays 'Xh Ym'. All formatters share this rule via the internal/durationfmt Go package rather than each reimplementing hour-based formatting.

**Why:** cloche status --all was showing a long-running poll task as 'main: 2065h12m' because the CLI, web handler, and console.js each had their own hour-only duration formatter with no day rollover. The fix extracted one shared Go helper (internal/durationfmt) used by both cmd/cloche and internal/adapters/web, plus a matching JS implementation in console.js, with table-driven tests covering the boundaries (59s, 60s, 59m59s, 1h, 23h59m, 24h, 6d23h, 7d).
