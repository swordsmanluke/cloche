Validation of a module-bound workflow step checks the bound workflow's contract: an input that nothing could provide is an error, while an input only a script step might write is a warning; `out.<key>` remaps must name outs the child declares.

**Why:** Script steps can write KV keys dynamically so static analysis can't prove their absence, but inputs with no possible source are definitely bugs.
