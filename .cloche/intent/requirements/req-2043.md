Task-tracker integration is deliberately a script contract — the `list-tasks` JSONL format plus five replaceable scaffold scripts (get-tasks/claim-task/prepare-prompt/close-task/unclaim) — not a typed plugin system.

**Why:** The script-contract abstraction landed instead of a plugin architecture, keeping the default beads-backed tracker swappable for Jira/ADO/GitHub Issues/etc. without needing a compiled plugin API.
