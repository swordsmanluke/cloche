Store and HTTP handler code that iterates over tasks, attempts, or prompt files must not issue one DB query or subprocess call per row. Batch into a single joined or IN query, and cache expensive per-file computation (e.g. `git log`) keyed on an invariant like the repo's current HEAD, rather than recomputing it per request.

**Why:** At this project's actual scale (~1,700 tasks, ~1,439 attempts), a per-row query or subprocess turns an endpoint into a multi-second (or 60s+) response — measured directly on `cloche status`, `cloche list`, the task-stack API, and the ledger API before each was fixed.
