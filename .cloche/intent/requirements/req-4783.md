A config override file named `<name>.merge.<ext>` (json, yaml/yml, toml) is merged into the matching project file; plain override files still replace. Merge failures (unparseable file or target, non-map top level, unsupported extension, a plain and merge override for the same target, multi-document YAML) fail the run at container start and never fall back to copying.

**Why:** Merging is opt-in per file so existing overrides behave as before; a silent fallback would hide a broken settings file.
