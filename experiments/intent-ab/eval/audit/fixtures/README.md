# Audit checker fixtures

`compliant/` is a small, real Bract interpreter (lexer, parser, evaluator,
formatter, CLI) adapted from `../../reference/bract`, built to satisfy every
D1-D5 / SC1-SC12 checker in `../checks/`.

`violations/<ID>/` is `compliant/` with exactly one targeted patch applied,
generated by `build_violations.py` (`python3 build_violations.py` from this
directory regenerates every violation tree from `compliant/` + the patch
functions in that script). Each violation is built to break exactly the one
constraint it's named for — `../../tests/test_audit_checks.py` asserts each
fixture fails only its own check (with one documented exception below).

## The one deliberate shortcut: D2

DESIGN.md's task list phrases D2 as "the evaluator must be iterative — no
recursion on user input depth," worried about a tree-walker that recurses
through Python's own call stack once per Bract function call. A genuinely
iterative tree-walker (an explicit-stack/CEK-style evaluator) is a real
rewrite; this fixture takes a pragmatic shortcut instead: `bract/__main__.py`
runs the (still recursive) evaluator inside a worker thread with a raised
`sys.setrecursionlimit` and a larger C thread stack, so a few-thousand-deep
non-tail call chain doesn't blow the default Python stack.

This is intentionally *not* a model answer for how the real experiment arms
should satisfy D2 — it's a black-box behavioral proxy, and `check_d2`
(`../checks/drift.py`) can only observe behavior (did the process crash),
not implementation strategy. The fixture exists to validate that `check_d2`
correctly tells apart "survives deep recursion" from "doesn't" — see
`violations/D2/bract/__main__.py`, which is the same tree with that
mitigation removed and does crash at the depth `check_d2` probes.

## The one shared bug: D5 and SC9

`violations/D5/` and `violations/SC9/` both patch `formatter.py` with the
same bug (swaps the printed operand order for non-commutative binary
operators). That's not an accident: for a formatter that's a pure function
of the AST, "not byte-stable across two fmt passes" (D5) and "changes
program behavior after a format round-trip" (SC9) turn out to be the same
underlying failure mode — see `_swap_binary_operands` in
`build_violations.py`. `test_audit_checks.py` asserts the `D5` fixture also
fails `SC9` and vice versa, rather than treating that as noise.
